# Attribute Set Definitions

Attribute sets are normally C# classes extending `AttributeSet`. An **attribute set definition** is a resource that describes the same thing in the inspector, from which the plugin generates that class for you. Designers can add stats to a project without opening a code editor, and the result is an ordinary attribute set: nothing downstream — effects, cues, requirements, Statescript resolvers, the `ForgeAttributeSet` node — can tell the difference.

If you are comfortable writing the class by hand, keep doing that. Definitions exist so that writing it is not a requirement.

## Creating a Definition

1. In the FileSystem dock, right-click a folder and choose **Create New → Resource**.
2. Pick **ForgeAttributeSetDefinition**.
3. Save it somewhere in the project (the location does not matter; the whole project is scanned).
4. Set **Attribute Set Name**, then add an entry to **Attributes** for each stat.
5. Save the resource. The C# class is generated at that moment.
6. **Build the project.** Until you do, the class does not exist yet.

The set name becomes the generated class name and the prefix of every attribute key, so `ItemAttributes` with a `Price` attribute produces the key `ItemAttributes.Price` — exactly what a hand-written set of the same name would produce.

For that reason **a definition cannot reuse the name of an attribute set you wrote in C#**, and the inspector refuses to generate one that does. The two classes would land in different namespaces and compile perfectly happily, but both would register their keys under the same `CharacterAttributes.` prefix and the editor's by-name lookups would resolve to whichever the runtime returned first. If you want a definition to replace a hand-written set, delete the class first.

### Attribute Set Definition

| Property | Description |
| --- | --- |
| `Attribute Set Name` | The set's name. Becomes the generated class name and the prefix of every attribute key. Must be a valid C# identifier and unique across the project. |
| `Attributes` | The attributes the set owns. |

### Attribute Definition

| Property | Default | Description |
| --- | --- | --- |
| `Attribute Name` | — | Becomes a property on the generated class. Must be a valid C# identifier and unique within its set. |
| `Default Value` | `0` | The value the attribute starts at. |
| `Min Value` | `0` | The lowest value the attribute can hold. |
| `Max Value` | `int.MaxValue` | The highest value the attribute can hold. |
| `Channels` | `1` | How many channels the attribute aggregates modifiers through. |
| `Decimal Places` | `0` | How many decimal places the stored integer stands for when shown to a player. Presentation only. |

> **Attribute values are integers**, by design — the simulation stays deterministic. A stat that needs decimals is stored scaled: a `Price` of `1000` with `Decimal Places` set to `2` reads as `10.00` to the player and stays `1000` to the simulation. Everything you type in the editor is raw. See [Attribute Values Are Integers](https://github.com/gamesmiths-guild/forge/blob/main/docs/attributes.md#attribute-values-are-integers).

## Generation

Generated classes are written to `res://forge_generated/attribute_sets/`, one `<SetName>.generated.cs` per definition, in the `Gamesmiths.Forge.Godot.Generated` namespace.

Generation runs when:

- **a definition is saved** — the code follows the resource automatically, or
- **you press "Regenerate Attribute Set Code"** at the top of any definition's inspector.

Either way the plugin regenerates **every** definition in the project, not just the one you touched, and deletes any `.generated.cs` whose definition no longer exists. That is what keeps a deleted or renamed set from leaving a stale class behind. Only files ending in `.generated.cs` are cleaned up, but treat the folder as owned by the plugin regardless and keep your own code elsewhere.

A definition named `ItemAttributes` with `Price` and `Weight` generates:

```csharp
// <auto-generated/>
// ...
using Gamesmiths.Forge.Attributes;

namespace Gamesmiths.Forge.Godot.Generated;

public partial class @ItemAttributes : AttributeSet
{
    public EntityAttribute @Price { get; private set; }

    public EntityAttribute @Weight { get; private set; }

    public @ItemAttributes()
    {
        @Price = InitializeAttribute(nameof(@Price), 1, 0, 1000000, 1, 2);
        @Weight = InitializeAttribute(nameof(@Weight), 1, 1, 99999, 1, 2);
    }
}
```

Identifiers are written with a leading `@`, which is C#'s escape for using any word as an identifier. It costs nothing and means an attribute named `class` or `event` still compiles. `nameof` strips the escape, so the registered key is the name you typed.

### The Build Step

The plugin cannot compile C# for you, so a definition becomes a real attribute set only after Godot builds the project. The definition's inspector tells you where you stand:

| Banner | Meaning |
| --- | --- |
| Green — *"This set is generated and built"* | The compiled class matches the definition. Nothing to do. |
| Yellow — *"Build the project for this set to take effect"* | The class does not exist yet, or exists but no longer matches the definition after an edit. Press **Build**. |
| Red — validation errors | Nothing was generated. Fix the listed problems first. |

The check compares the compiled attributes by value — default, minimum, maximum and decimal places — not merely by name, so the yellow banner also catches the easy-to-miss case where you edited a bound or a default and the names stayed the same. Channel count is the one input it cannot verify, because `EntityAttribute` keeps it private.

### Before the Build

You do not have to build before you can *reference* a new set. The attribute pickers list compiled sets **and** sets that only exist as definitions, so you can define `ItemAttributes` and immediately point a modifier at `ItemAttributes.Price`. The reference is stored as text and resolves normally once the class exists.

Only definitions that would actually generate are offered — one with a validation error never becomes a class, so it is kept out of the pickers rather than inviting a reference that could never resolve.

Two consequences worth knowing:

- A pending set looks the same in an attribute picker as a built one. The definition's own inspector is where build status lives.
- The **`Attribute Set Class` dropdown on a `ForgeAttributeSet` node is the exception**: it lists compiled sets only. Choosing a class there reads its attributes to seed the node's initial values, which a set that does not exist yet cannot supply. Build first, then assign the set to a node.

## Using a Generated Set

Exactly like a hand-written one:

- Put its name in a [`ForgeAttributeSet`](nodes.md#forgeattributeset) node's `Attribute Set Class` and configure per-instance starting values there.
- Pick its attributes in any attribute dropdown — `ForgeModifier`, `ForgeCue`, attribute requirements, Statescript's attribute resolvers.

## Adding Logic to a Generated Set

The generated class is `partial`, so per-set behaviour lives in a separate file that the generator never touches. This is how you keep the clamping and reaction logic that a code-authored set would have:

```csharp
// res://scripts/ItemAttributes.Custom.cs
using Gamesmiths.Forge.Attributes;

namespace Gamesmiths.Forge.Godot.Generated;

public partial class ItemAttributes
{
    protected override void AttributeOnValueChanged(EntityAttribute attribute, int change)
    {
        // React to changes here.
    }
}
```

The namespace has to match. `AttributeOnValueChanged`, `PreEffectExecute` and `PostEffectExecute` are all `protected virtual` on `AttributeSet` and available to override.

Put this file outside `res://forge_generated/`, since that folder is rewritten on every run.

## Renaming and Deleting

**Renaming a set or an attribute breaks existing references.** Attribute keys are stored as text (`ItemAttributes.Price`) inside effects, cues and Statescript graphs, and renaming the definition does not rewrite them. Those references become dangling and show as `(missing)` in the pickers, which is deliberate — the picker never silently repoints a broken reference at something else, so you can see exactly what needs fixing.

If you rename, plan to fix the references yourself. The same applies to deleting a definition: the class disappears on the next generation, and anything still pointing at it shows as missing.

## Validation

A definition is skipped, with its problems listed in the inspector and in the Output panel, when:

- the set name or an attribute name is not a valid C# identifier (letters, digits and underscores, starting with a letter or underscore),
- two definitions share a set name,
- a hand-written C# class extending `AttributeSet` already uses the set name,
- two attributes in one set share a name,
- an attribute's minimum is above its maximum,
- an attribute's default value falls outside its own minimum and maximum,
- an attribute slot is empty, or
- the set has no attributes.

Other definitions still generate; one bad definition does not block the rest.

An invalid name comes with a suggested replacement — `"Fire Damage"` suggests `Fire_Damage`, `"2Handed"` suggests `_2Handed`. The suggestion is never applied for you. An attribute's name is part of the key that effects, cues and graphs store, so rewriting it silently would repoint every reference at a key you never typed; you get told what would work and decide whether to take it.

## Version Control

Commit the contents of `res://forge_generated/`. They are ordinary source files, and committing them means a fresh clone compiles without anyone having to open the Godot editor first. They are deterministic, so they only change when a definition changes.

## Limitations

- **A build is always required** before a new or edited set exists at runtime.
- **Only `.tres` definitions are found.** Definitions are discovered by reading the `script_class` field in the resource header, which binary `.res` files do not expose in readable form. Saving from the inspector produces `.tres`, so this only matters if you deliberately convert one.
- **No per-attribute custom logic in the resource.** Anything beyond the values in the table above belongs in the partial class.
